## 设计与实现选择

- 按已确认的多俱乐部平台设计数据权限；主办方与队长是不同角色。
- SwiftUI 原生界面使用系统字体、SF Symbols、语义色和原生导航；后台使用 React + Ant Design。
- 后端采用 NestJS + 参数化 PostgreSQL SQL。首版不引入 ORM、微服务、Redis 和复杂动态规则引擎。
- 只使用成人虚构演示名单。正式人员/监护模型、规程版本和跨队资格约束在后续规则确认后实现。
- 本地服务只监听 loopback，不部署到公共网络。GitHub 是代码仓库，不是正在运行的 API 服务器。

## TDD 证据

实际执行“新增一条行为测试 → 失败 → 最小实现 → 通过”，测试通过 HTTP 公开接口调用 NestJS 和真实 PostgreSQL。

| 测试增量 | RED | GREEN |
| --- | --- | --- |
| 游客查询赛事和详情 | 404，预期 200 | 数据库赛事返回成功 |
| 会话/队伍隔离/退出 | 404，预期 401 | 仅返回自己的队伍，退出后旧令牌无效 |

补充验证非法名单、重复姓名、规则未确认、设备级别不符、截止报名，以及关闭开发入口和生产环境禁止演示鉴权。

每次测试创建随机隔离 schema，结束仅删除该测试 schema。开发演示数据保持不变。

## 环境问题与处理

本机 Xcode 26.5 带 iOS Simulator 26.5 SDK，已有运行时为 iOS 26.4。scheme destination 解析报 `iOS 26.5 is not installed`，但直接指定 target + simulator SDK 成功构建。已将可重复命令整理为 `npm run ios:build`；未下载额外模拟器，也未修改系统 Xcode。

最初无应用 Keychain entitlement 的模拟器构建能启动，但登录不能安全存储会话。增加仅针对 Simulator SDK 的本地 application identifier 和 Keychain group，使用临时签名后，实际登录成功。正式真机签名必须另行配置。

后台原生 datetime-local 输入在当前浏览器控制环境中没有保留值。替换为 Ant Design DatePicker，实测能提交时间并成功发布。

## 跨端人工验收

使用浏览器和 iPhone 17 Pro / iOS 26.4 模拟器实际操作：

1. Web 选择“青空赛事运营”，发布“联调体验赛 · 首次飞行”。
2. iOS 从 API 读取到相同标题、时间和场地。
3. iOS 登录“林教练”，选择“青空一队”，确认三名虚构飞手名单并提交。
4. Web 刷新后出现对应待审记录；确认通过并填写“跨端联调通过，演示队伍名单已确认。”。
5. iOS 重启后仍保留登录；进入“我的报名”看到“已通过”及与 Web 一致的审核备注。页面提供手动刷新按钮；不假装已接入实时推送。

测试记录与当前未完成项应在后续迭代持续更新，不能将本地演示通过等同于正式赛事和上架验收。
