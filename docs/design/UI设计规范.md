# Drone Match 界面设计规范

第一轮目标（历史记录；当前 iOS 以文末第二轮规范为准）：以足球中国截图的信息组织为参考，把首版展示感界面改为可日常使用的无人机足球赛事产品。保留已实现的报名、审核、登录和机构权限。

## 设计判断

旧版主要问题是宣传语占据首屏、相同大卡片反复出现、图标被当成赛事海报、后台缺少操作优先级。参考截图的价值在于搜索、快捷入口、状态筛选和赛事详情层级，不复制其商标、图片或足球项目字段。

采用用户指定的 taste-skill 与 Anthropic frontend-design 的审查和内容原则。taste-skill 原文不覆盖原生移动端、后台表格，故只采用适用的视觉判断；具体组件遵循 SwiftUI 和 Ant Design 的原生交互。

## 视觉基础

| 色彩 | 值 | 用途 |
|---|---|---|
| 品牌绿 | #008A46 | 主要操作、选中状态、通过状态 |
| 运动绿 | #00B85A | 品牌符号与装饰，避免白色小字直接叠放 |
| 正文 | #18221D | 标题与主体内容 |
| 次要文字 | #66716B | 时间、地点、辅助说明 |
| 页面底色 | #F4F6F5 | 模块分组 |
| 表面 | #FFFFFF | 列表、表单、操作区域 |

iOS 使用系统中文字体（苹方）和 SF 数字：页面标题 24–28pt，模块标题 19–20pt，正文 15–17pt，辅助文字 12–13pt。支持动态字体，深色模式使用语义色。Web 使用系统字体，页面标题 24px，正文 14px，数据 30px；避免全大写英文眉题和装饰性前导零。

## 页面结构

所有主要内容左对齐。运动感集中在首页的一张无人机足球主题图，操作区保持平静。赛事列表优先展示名称、日期、城市、级别和报名状态；后台优先显示待审核报名。

```
iOS 首页                    Web 工作台
品牌 / 全国赛事              机构导航 | 页面 / 刷新
搜索赛事                     工作台 / 发布赛事
主题赛事（可进入详情）         赛事数 / 待审核 / 已通过
报名 / 队伍 / 记录 / 指南      待审核报名表
我的报名进度                 近期赛事
近期赛事列表                 
五栏原生导航
```

- 首页主题图是通用的无人机足球视觉插画，不宣称为实际赛事摄影。
- 列表使用日期信息块，不凭空为不同赛事创造海报或主办方标志。
- 报名状态除颜色外必须有文字，未通过使用橙红色，待审核使用橙色。
- 每个入口必须可用；未接入的视频功能明确说明尚未开放，提供返回赛事的操作。
- 生涯只显示真实报名与队伍数据，不把报名通过算作比赛成绩。
- 后台去除营销文案与装饰海报，使用日期、人数、级别和审核动作。
- 44pt 最小点击区域，长标题换行，加载失败可重试，筛选为空可恢复。
- 演示身份与虚构资料说明保留在账号和表单中，不将开发版包装为已上线服务。

## iOS 第二轮规范 · 2026-09-07

以真实任务优先组织信息，替代上文五栏和通用主题图的方案。Web 保持第一轮方案。

- 主导航为赛事、队伍、我的。未接入的视频及重复报名数据的生涯不占主栏目。
- 赛事为默认页，直接输入搜索；城市菜单、设备级别和可报名筛选作用于真实赛事数据。按月份展示日期、标题、场地与状态，平铺列表以分隔线组织，不重复套卡片。
- 去除通用生成球体图与四色快捷入口。没有对应赛事素材时直接展示信息，不用同一张图暗示不同赛事身份。
- 主要操作使用深绿（浅色模式 RGB 0/0.46/0.25），正文和背景使用系统语义色，系统动态字体、原生导航与表单。状态用文字及色点共同表示。
- 赛事详情直接提供时间、截止、场地、主办方、规程及本赛事报名入口；报名成功显示具体记录，不跳全部记录。
- 队伍名单逐人维护，添加、移除、校验与后端保存一致。报名中的建队预选赛事级别，完成后自动选中，用户再次确认名单。
- 个人中心保留报名、指南和关于。开发身份说明保持真实，不伪装正式账号系统。
- 数据页失联时显示错误、上次成功更新时间和重试入口；旧报名状态不暗示实时同步。

已在 iPhone 17 Pro / iOS 26.4 查看赛事首页、确认报名、队伍编辑、报名详情和断网状态。完整 VoiceOver、大字体、横屏及其他尺寸仍需后续专项验收。
